# 슬레이브 측 gap 분석 — 설계 대비 미구현/부분구현

## 0. 조사 전제: live 슬레이브 경로

**monolith가 live다.** `cs/CMakeLists.txt:473-474`가 컴파일하는 transaction 소스는
`log_applier_sql_log.c`와 `log_applier.c` 둘뿐이다. pre-reset 모듈 시도의 흔적으로 언급된
`log_applier_gate.cpp / _queue.cpp / _worker.cpp / _coordinator.cpp / _inflight.cpp`는
**이 트리에 존재하지 않는다**(`ls`로 확인; `log_applier_sql_log.c`만 존재). `log_applier.c`도
그 모듈들을 참조하지 않는다. `build_x86_64_release/build.ninja`가 산출하는 오브젝트도
`log_applier.c.o`, `log_applier_sql_log.c.o`뿐이다.

→ 모든 슬레이브 동작은 `src/transaction/log_applier.c`(14187줄) 한 파일에서 확인했다.
"모듈화 안 됨"은 의도된 보류이므로 gap으로 보고하지 않는다.

## 2. 우선순위별 MISSING / 미완 목록

### A. 정확성-critical

1. **cub_server 재시작 epoch 경계 미구현 (항목 11).**
   마스터 `cub_server`가 승격 없이 빠르게 재시작하면 writeset history(프로세스 메모리)가
   사라져 재시작 후 같은 키 트랜잭션이 `dependency=NULL`로 독립 배정된다. 슬레이브에서
   재시작 전 트랜잭션이 실행 중인데 재시작 후 트랜잭션이 먼저 COMMIT → 마스터 COMMIT
   순서와 슬레이브 DB COMMIT 순서 역전 가능. ★위반이 무성 skip이라 순서=정확성인 설계에서
   치명적. 코드에 흔적 전무. 설계 12장이 "재시작 정확성이 남은 PoC"로 자인한 항목이고,
   마스터(barrier 라벨 기록)+슬레이브(경계 drain) 양쪽 변경이 필요하다. **슬레이브 측 최대 gap.**

2. **역할 전환 drain이 기본 OFF (항목 4/12).**
   비-prefix 승격 시 홀을 드레인해 prefix까지만 승격시키는 보호가 `ha_applylogdb_drain`
   (기본 false, hidden) 뒤에 있다. 켜지 않으면 Hook A DONE 게이트·backstop·C1이 전부
   비활성(`la_drain_enabled()` → `prm_get_bool_value` `9357`). 실제 failover 승격 실측도
   미완(9.2). 승격 경로의 정확성 보장이 옵션 의존 상태.

### B. 정확성 영향 있으나 범위 제한 / 미검증

3. **statement·DDL 재적용 whitelist 미구현 (항목 2b).**
   복구 구간에서 DDL 재생성·statement DML 재적용 오류는 window 무시 대상이 아니라 항상
   `fail_counter++`. 재시작이 statement 복제를 포함한 구간을 재적용하면 불필요한 fail
   누적·복구 경로 교란 가능. 설계가 미구현으로 명시(9.1.3)하나 정확성 영역.

4. **SYSOP_END 재시작 멱등의 엣지 미검증 (항목 9).**
   전용 완료마커 없이 recovery-window + 전체-txn-skip에 의존. 복제항목 없는 SYSOP_END를
   무시할 때 develop이 그 위치에 `committed_lsa`를 영속한 상태에서 정식 구현으로 기동하는
   재시작 시나리오(9.1.1 마지막) 미확인.

### C. 성능 / production polish (정확성 무관)

5. **worker 수·queue 용량·메모리 한도 하드코딩 (항목 10).**
   `LA_APPLY_WORKER_COUNT=10`, `QUEUE_CAPACITY=1024` 등 전부 `#define`. 설계/handoff가
   시스템 파라미터화를 요구. 러프 PoC 포트라 예상된 보류지만 production 전 필수.

6. **완료집합 back-pressure 미채택 (9.1.4) / result queue 포화 교착 (9.1.8).**
   프론티어 위 홀 목록 고정크기(`LA_GATE_SET_CAPACITY`), 초과 시 명시적 실패. 상시
   back-pressure 정책 미구현. 슬레이브 측 안정성 polish.

## 3. 설계대로 잘 반영된 부분 (gap 아님, 확인용)

- recovery window + 행 DML error-skip, SYSOP_END까지 커버 (항목 1/2/3)
- gap-free frontier·committed_lsa 단조 전진·required_lsa 보존·committed_rep_lsa 비오용 (항목 5/6/7)
- `dependency_is_ref`(코드명 `dependency_is_read`) 게이트 분기 — ref는 frontier 대기, WRITE는
  완료집합 멤버십, 불변식 4/5 정확 구현 (항목 8)
- SYSOP_END fragment 분리(`la_detach_sysop_fragment` `10145`)·완료집합/frontier 등록
  (`2486-2488`)으로 의존자 통과 (항목 9 기반 동작)
- drain 완료 판정 3-조건(pending·in-flight list·gate order 공집합) (항목 4 기반)
