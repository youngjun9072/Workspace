# MySQL 병렬 복제 의존성 추적 — 버전 연혁

> 조사 메모 · 2026-06-08
> 주제: MySQL 병렬 복제에서 `COMMIT_ORDER`, `LOGICAL_CLOCK`, group commit, WRITESET의 도입·변경·제거 시점 정리.

## 버전 연혁

| 시점 | 사건 |
|---|---|
| 5.6 | `DATABASE` 단위 병렬(스키마별). commit order/logical clock 방식은 아님. |
| 5.7.2 | `LOGICAL_CLOCK` 병렬 복제 도입(logical clock v1). 같은 commit parent(=같은 group commit)만 병렬 적용 가능 → group commit이 사실상 병렬의 전제(필수). |
| 5.7.6 | logical clock v2. lock interval 기반으로 바뀌어 group commit 의존이 끊김(더는 필수 아님). |
| 8.0.1 | `binlog_transaction_dependency_tracking` 변수 도입(`COMMIT_ORDER`/`WRITESET`/`WRITESET_SESSION`). 기본값은 `COMMIT_ORDER`, `WRITESET`이 옵션으로 처음 사용 가능. |
| 8.0.27 | `replica_parallel_type=LOGICAL_CLOCK`이 기본, worker 기본 4 → 멀티스레드 복제가 기본. |
| 8.0.35 / 8.2.0 | `binlog_transaction_dependency_tracking` deprecated. |
| 8.4.0 (LTS) | 변수 제거(= `COMMIT_ORDER` 모드 삭제). 서버가 기본으로 `WRITESET` 동작(= 기본이 `WRITESET`이 된 시점). |
| 9.x (현재) | 8.4와 동일. 변수 없음, 항상 `WRITESET` 동작. 9.7.0 소스에서 제거 확인. |

## 질문 항목별 직답

| 질문 | 답 |
|---|---|
| commit order 시작 | 의존성을 commit 순서(logical clock)로 계산하는 방식은 5.7.2. 명시적 `COMMIT_ORDER` 모드/변수는 8.0.1부터이고 기본값이었다. |
| group commit을 필수로 쓰기 시작 | 5.7.2(logical clock v1). |
| group commit이 필수가 아니게 됨 | 5.7.6(logical clock v2, lock interval 기반). |
| writeset 사용 가능 시점 | 8.0.1(옵션). |
| 기본이 writeset이 된 시점 | 8.4.0(변수 제거 + 기본 `WRITESET` 동작). |
| commit order 삭제 시점 | 8.4.0. 그 전 8.0.35/8.2.0에서 deprecated. |

## 뉘앙스

8.0의 `COMMIT_ORDER`도 내부적으로는 logical clock v2(lock interval)라 group commit에 직접 묶이진 않는다. 다만 공식 문서가 "`COMMIT_ORDER` = commit timestamp 기반"이라고 표현하고, 8.0에서는 group commit 크기가 `last_committed` 값에 간접 영향을 준다.

따라서 "group commit 필수"는 5.7.2~5.7.5(logical clock v1) 시절에 한정된 설명이다. 이 구분은 hackmysql의 group commit / transaction dependency tracking 글이 명확히 정리한다.
